---
name: migration
description: Create an EF Core migration for TakaLeaf through the CI workflow after changing entities or ModelConfiguration.
argument-hint: "[MigrationName, e.g. AddTags]"
disable-model-invocation: true
---

Create the migration **$ARGUMENTS** the project's way. Migrations are generated by CI and are never
written or edited by hand.

1. Make sure the entity and `Data/ModelConfiguration.cs` changes are complete (check constraints,
   indexes with `HasFilter("deleted_at IS NULL")` where uniqueness should ignore deleted rows,
   `ConfigureSynced()` for user tables, `DbSet` in `AppDbContext`).
2. Commit those changes on a feature branch (not `main`).
3. Write the name to the request file and push:
   ```bash
   echo $ARGUMENTS > backend/.migration-request
   git add backend/.migration-request && git commit -m "Request migration $ARGUMENTS"
   git push
   ```
4. Wait for the `EF migration` workflow (`gh run list --workflow ef-migration.yml --limit 1`), then
   `git pull` and read the new file in `backend/TakaLeaf.App/Data/Migrations/` to check it does only
   what you meant (no dropped columns or tables you did not intend).
5. If a local .NET SDK is available you may instead run
   `dotnet ef migrations add $ARGUMENTS --project backend/TakaLeaf.App --output-dir Data/Migrations`,
   but CI generation is the default so the result matches the pinned SDK.
